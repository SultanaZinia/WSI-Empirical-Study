| 2026-11-01 | LTS implementation | — | `selectors/lts.py`, from the paper text (HTML v1); the paper gives no code, hyperparameters, encoder, scorer size or Φ_K. Kept from the paper: Transformer scorer over all N tokens + linear score, z-scored per slide (Eq. 3); training keeps all N tokens with soft keep weights α (Σα = K, Eq. 4), VP noise x̃ = √α x + √(1−α) ε (Eq. 5) and a per-token denoiser (one Transformer block with a diagonal mask); cosine τ anneal; inference = hard top-K, denoiser off (Eq. 2); no auxiliary losses. **Our choices:** (1) scorer = Linear → 512, 2 pre-norm Transformer blocks (8 heads, FFN 1024, dropout 0.25), global attention. The paper's method section says Transformer blocks but its conclusion calls the scorer "localized"; user decision 2026-11-01: follow the method section. (2) Φ_K = sigmoid((ŝ − λ)/τ) with λ by bisection so Σα = K, λ held constant for the gradient. (3) τ cosine 1.0 → 0.1 over the first 50 epochs (= `stop_epoch`, so annealing ends before early stopping can fire), then held. (4) α clamped to [1e-6, 1 − 1e-6] before the square roots: at low τ, α saturates to exactly 0/1 and the gradient became NaN (found on toy data). (5) Denoiser width = feature dim, 1 head, FFN 512. (6) LLM + projector replaced by the shared gated-ABMIL head on the K kept (inference) or N denoised (training) tokens, trained with the shared CLAM-default recipe. (7) One model per K | Every numbered choice is a guess where the paper is silent. Positional indices (the paper keeps them for RoPE in the LLM) are not used: our head has no positions. The train/inference mismatch (denoised noisy tokens vs clean raw tokens) is the paper's own design |
| 2026-11-01 | SLICEChat implementation | — | `selectors/slicechat.py` + `selectors/mamba.py`, following the official encoder code (github.com/ali-kerem/SLICEChat-encoder @ c665990, Apache-2.0: `vision_mamba.py`, `token_compressors/cropr.py`, `mamba_custom.py`, `sorters/`). **Kept from the code:** tokens in raster order (row, then column); blocks of bidirectional Mamba-1 (separate forward/backward conv + SSM parameters, shared in/out projections, outputs averaged) then one pre-norm Transformer layer; a pruner after every block but the last (5 of 6); each pruner = 1 learned query, 1 head, key + value projections, MLP on its pooled output; score = pre-softmax query·key; removes the one contiguous Hilbert-curve window (10 bits) with the lowest score sum; survivors re-sorted to raster order; pruner pooled outputs trained by an auxiliary loss on detached tokens (summed over pruners, weight 1, as in `loss.py`/`train.py`); per-stage count N_{l+1} = round(k·N_l) (reproduces the paper's Fig. 3: 4,785 → 3468, 2514, 1822, 1321, 957). **Our choices (user decision 2026-11-01: smaller encoder on UNI):** (1) no MAE pretraining and no CLIP/LLM stages: one stage, trained from scratch with slide labels by the shared CLAM-default recipe (encoder, pruners and heads jointly; the paper freezes a pretrained encoder while training pruners).
